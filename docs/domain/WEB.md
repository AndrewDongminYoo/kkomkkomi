# Web

Moved unchanged from `CLAUDE.md` § Architecture on 2026-11-02.

- **Web.** No Flutter web app is planned. `web/` is the deploy root of the static landing page, which lives in this repository and not in a separate one, and `web/index.html` is that page (decided 2026-10-01). It is one hand-written HTML file, so no Flutter build produces or checks it. `web/og.png` and the two icons under `web/icons/` are renders of the cards under `tool/web_assets/`, and `tool/web_assets/render.sh` owns how to make them again. The one `web/google*.html` file is the file with which Google Search Console verifies ownership of the URL-prefix property `https://kkomkkomi.web.app/` (issue #53), so keep its name and its content unchanged and keep it deployed. `web/sitemap.xml` lists the landing page and the two privacy pages, and `web/robots.txt` allows every path and names the sitemap. A report URL never goes into the sitemap. The report page carries `noindex, nofollow`, and `robots.txt` does not block `/r/`, because a crawler that may not fetch a page cannot read its `noindex`. A new public page goes into the sitemap. Firebase Hosting serves `web/` at `https://kkomkkomi.web.app`, and `firebase deploy --only hosting` publishes it. A deploy, and a change to the deployed security rules, needs the user's approval each time. The web report page is `web/report/index.html` with its script and style beside it, plain files without a build step, and `firebase.json` rewrites every path under `/r/` to it: `/r/<pageId>/<visitId>` shows one report and `/r/<pageId>` the list of the reports of the client page. It reads the configuration of the project from the reserved Hosting path `/__/firebase/init.json`, so no tracked file holds it, and it loads no Firebase SDK, because `/__/firebase/init.js` initializes only the SDK of version 8 and earlier (https://firebase.google.com/docs/hosting/reserved-urls). It reads the documents through the Firestore REST API and each photo from the Storage REST API without a download token, so the rules check every read, and a revoked or unknown page ID shows one message. It puts every text from the backend into `textContent`. A zone that is partly done or not done carries `status` and `reason`, which `FirebasePublisher` leaves out of a done zone, and the page reads a missing `status` as done and a value that it does not know as not done, as the device does; it shows the summary, the status badge, and the empty slot texts of the PDF. A report with `unbranded: true` shows no footer text and keeps the privacy policy link, and the list of the reports of a page shows no footer text only when it lists a report and every listed report is unbranded. `firestore.rules` accepts that key, with the value `true` only, from a writer whose `revenueCatEntitlements` token claim is a list that holds `basic` or `pro`. `test/web/` tests it in Node with fixture data and a fake document (`merry run web`), and `test/rules/web_report.test.js` tests its reads in the emulators. The visit report screen shares the link only after the publish job of the visit is done, so a shared link never opens a page or a report that the backend does not hold, and it opens the share sheet then only while it is on top and no PDF share is on its way, else the next press publishes again and shares, and it tells the person at the first link of a client that anyone with the link can open the reports. `share_plus` opens the share sheet for the link, through `SharePlusLinkShare`. The privacy policy is `web/privacy/index.html` in Korean at `/privacy/` and `web/privacy/en/index.html` in English at `/privacy/en/`, plain HTML with one style sheet and no script, and the footer of the web report page links to it. Each clause states what the code, the rules, or a command output shows, and the pull request that added the pages lists the source of each clause. A change to what the app keeps, sends, shows, or deletes updates both pages together. `test/web/privacy.test.mjs` checks the files of the pages in Node, which measures no layout.
