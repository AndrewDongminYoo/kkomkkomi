# Identity

Moved unchanged from `CLAUDE.md` § Architecture on 2026-11-02.

- **Identity.** `Identity.currentUserId()` gives the ID of the current user, or null while identity is unavailable, and it does not throw. `FirebaseIdentity` calls `Firebase.initializeApp()` without options, which reads the native config file of the platform, and then gives the ID of the account that the device holds or signs in anonymously. A start or a sign-in that fails gives null, and the next call starts Firebase and signs in again. `bootstrap()` asks once, and the publish queue asks again before each job, so a job waits with its retry delay while identity is unavailable. `RevenueCatEntitlements` asks before each call, so after Delete All Data the release flavor also signs in with a new anonymous account when the plans screen reads the plan, or when the add control of the client list reads it at the Free limit, and the privacy pages say so in section 6. Calls at one time share one attempt. `Identity.deleteAccount()` deletes the account that the device holds and never signs in: no account, or one that the backend no longer has, counts as deleted. It first waits for a sign-in that is on its way, such as the one of the start of the app, so that the sign-in cannot make an account after the delete. The FlutterFire documentation of `User.delete` says that `requires-recent-login` does not apply to an anonymous user, and an anonymous account cannot sign in again to fix it, so that code is a failure of the deletion step like any other. `Identity.hasPaidEntitlement()` tells whether the current user holds a paid entitlement, and it does not throw. `FirebaseIdentity` waits for a sign-in that is on its way, never signs in, and reads the `revenueCatEntitlements` claim from `User.getIdTokenResult(true)`, a newly issued token at each call, so a claim that the extension removed after an expiry or a transfer does not survive in a cached token. Paid means a list that holds `basic` or `pro`, as `paid()` in `firestore.rules` reads it; no account, a missing network, and any failure give false. The Windows runner has no native config file, so there the start fails and identity stays unavailable. No build and no test checks the start of Firebase on a device: the tests replace `Firebase.initializeApp` and `FirebaseAuth` with fakes.
