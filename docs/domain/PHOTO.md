# Photos

Moved unchanged from `CLAUDE.md` § Architecture on 2026-11-02.

- **Photos.** `App` uses `InAppCameraPhotoCapture` by default on Android and iOS. Its rear-camera route opens only after a before/after action, takes one still with audio disabled, and returns to the visit. `StillCameraCubit` owns controller initialization, serialized disposal, lifecycle generations and cancellation; late answers never attach a photo. `TemporaryCameraPhotoFiles` normalizes visible orientation, preserves the whole image, limits the longest edge to 1600 pixels, encodes JPEG at quality 80 and sanitizes metadata. `OwnedCameraPhotoCapture` releases only registered camera results after the document copy settles, including a failed copy; cleanup failure does not change the capture/save outcome, and gallery files remain borrowed. `ImagePickerPhotoCapture` selects one gallery photo through `image_picker`, retains the legacy camera path on unsupported platforms and owns picker size/quality limits. Gallery selection requests no full metadata. `ZoneRecord` keeps the source of each new photo; old sources are unknown, and reports label gallery photos. `OpenCapture` stores the source too, so Android recovery keeps it. `DocumentsPhotoStore` also normalizes PNG input to a white-backed JPEG; unsupported input fails before saving. Neither picker path records a capture time. `DocumentsPhotoStore` copies the picked file into `photos/<visitId>/` under the application documents directory, under a new name for each capture, and a `PhotoRef` holds the path relative to that directory. The copy goes through `withoutLocation`, which keeps the image data, the JFIF header, an ICC profile, and the Adobe segment, drops every other application segment (Exif, XMP, IPTC), every comment, and whatever follows the end of the image, and writes the Exif orientation back in a segment of its own, because both picker plugins leave the rotation in that tag and do not turn the pixels (issue 20). After PNG input is converted to JPEG, `withoutLocation` rejects bytes that are not a well-formed JPEG with a `FormatException`, so unsupported or malformed input makes the save fail and the capture shows a failure notice while keeping the previous photo. The publish queue and the PDF of the visit report run the function again on the bytes that they read, for a photo that an earlier version stored with its location; the queue stops such a job with `PublishFailure.photoNotJpeg` when the file is no well-formed JPEG. The file that the picker writes into the cache directory keeps the location on Android, and the one in the temporary directory can keep it on iOS. The files that an earlier version stored keep it on the device, and the objects that an earlier version uploaded keep it in Storage, because the queue does not upload a photo again that `published_photos` marks as arrived. `tool/photo_fixtures/make.py` makes the JPEG fixtures of these tests. `VisitCaptureCubit` sends the whole visit to the repository at each photo, each note edit, each status change, and each reason edit. A note edit does not wait for the save before it, so `VisitRepository.save` must apply saves in the order of the calls, and a capture waits for the answer to the newest save before it opens the camera. It deletes the file of a replaced photo only after storage took the new one. While storage does not hold a note, a status, or a reason, the screen keeps a notice with a control that saves again. The screen takes no back press while one of them is on its way to storage, and it asks before a person leaves with one that storage did not take. `ios/Runner/en.lproj/InfoPlist.strings` and `ios/Runner/ko.lproj/InfoPlist.strings` hold the camera usage description in English and in Korean, and `ios/Runner/Info.plist` keeps the Korean text as the fallback for a key that a strings file does not have. They also hold a photo library usage description, which describes selecting before/after zone photos from the library. Android declares `CAMERA` for the in-app preview, removes transitive microphone and legacy external-storage permissions, and marks camera hardware optional. iOS requests camera access with audio disabled; no microphone purpose key is added. Android can end the app while the camera app is open, and the photo of that capture then does not reach `takePhoto` (issue 7). For external picker operations, `VisitCaptureCubit` stores the visit, the zone, the slot and the source as the one row of `open_capture`, refuses to open the picker when storage fails, and removes the row when the picker answers. An in-app camera session instead clears any previous external intent and writes none; interruption requires a new capture rather than recovering a camera result. At the next start, before the app runs, `RecoverLostCapture` reads that row, asks `PhotoCapture.retrieveLostPhoto`, which calls `retrieveLostData` of `image_picker`, keeps the file with `PhotoStore`, saves the visit, and removes the row. The plugin writes the lost answer on a background thread after the restart, so while the camera has no photo the step asks again for 2 seconds (`RecoverLostCapture.defaultRetryDelays`, an estimate that no device measured) and then keeps the row for the next start; a new capture clears the answer of the plugin and replaces the row, so a kept row never names another capture. A row for a visit or a zone record that does not exist, and any row where `PhotoCapture.keepsLostPhotos` is false (every platform but Android), is removed without asking the camera, and a camera that cannot be asked leaves the row for the next start. The visit screen then says whether the visit holds the photo. `InAppPhotoCapture` returns the directly observed shutter-request time from this preview. `StillCameraCubit` samples the injected device clock immediately before dispatching the accepted shutter request, without an intervening await; this is an app request observation, not native sensor exposure evidence. `ZoneRecord` stores that observation as nullable UTC microseconds, and PDF/preview captions format it in the current device local time. The existing picker adapter does not implement that port, so picker, gallery, old and recovered photos have no capture time. No capture time enters `PublishedReport` or Firebase.
