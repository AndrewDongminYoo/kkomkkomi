# Report

Moved unchanged from `CLAUDE.md` § Architecture on 2026-11-02.

- **Report.** `ReportDocument.fromVisit` in `lib/export/` builds what a report prints from a visit, its client, and the company profile, and it leaves out a zone record without a photo and without a note. A zone record without a photo and with a note stays, with two empty slots. The preview of the visit report screen and `renderReportPdf` both show that document, so they hold the same zones, and both show the whole of each photo in a slot of the ratio `reportSlotAspectRatioOf`: 3:4 only when both photos of the zone display as portrait after Exif rotation, and 4:3 otherwise, including square photos and missing or unreadable preview photos. `VisitReportCubit.load` reads the photo orientation through `PhotoStore.read`, keeps only the portrait photo references, and keeps the report accessible with the existing broken-image placeholder for a failed photo; PDF sharing still reports unreadable files as a share failure. A portrait row and its zone name stay together on one PDF page, so A4 holds one portrait zone per page. `lib/export/` imports only the domain and `package:pdf`, and no Flutter library, and `test/export/boundary_test.dart` fails when a file there imports another library. So the caller gives the renderer what needs Flutter or a file: the texts as a `ReportLabels` value from the ARB files, the bytes of both fonts from the `ReportFont` port, the photo bytes from `PhotoStore.read`, and `showsFooterText`, which `VisitReportState.showsFooterText` holds for the preview and the PDF alike (see "Current state" for where it comes from). `PrintingReportShare` is the one file under `lib/` that imports `printing`, and `test/presentation/printing_import_test.dart` fails when a second file imports it. On Android and iOS the plugin answers when the share sheet opens, so the app does not know whether the person sent the file. The plugin writes the file under the name that it is given, and a name that the file system refuses makes the share do nothing without an error, so `reportFileName` removes the characters that a file name cannot hold and limits each part in UTF-8 bytes. `VisitReportCubit.share` catches every object, because `pdf` holds code that throws objects that are no exception, such as the `String` of `PdfJpegInfo`, and the screen takes no touch while a share is on its way. The PDF is rendered on the UI isolate. `assets/fonts/NotoSansKR-Regular.ttf` and `assets/fonts/NotoSansKR-Bold.ttf` are the fonts of the PDF, with their license in `assets/fonts/OFL.txt`. They are the static Regular and Bold instances of Noto Sans KR version 2.004 from the Google Fonts download, with the same 23,174 code points. The PDF needs a static file for each weight, because `pdf` reads no weight axis and prints a variable font at its lightest weight (checked with `pdf` 3.13.1 on 2026-10-06). The company name, the title, and the zone names print in Bold, and the PDF holds only the glyphs that it uses. A character that the font does not have, such as an emoji, prints as a crossed box. Known limits, which the adapter cannot see: when the plugin cannot write the file, no share sheet opens and the call still answers that it did, and on Android the plugin leaves each shared file in the cache directory of the app, where only the end of the app process or the system removes it.
