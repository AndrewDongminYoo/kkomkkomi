# M1 brief 7: web report page and link share

Design: `docs/specs/2026-10-01-m1-local-first-design.md`, section "Phase B".
Read the design and `CLAUDE.md` before you write code.
This brief depends on briefs 1 to 6.

## Goal

A client opens a link from KakaoTalk and sees the report, and the worker shares that link from the app.

## In scope

- A static report page under `web/` that reads one report and its photos, and a history view that lists the reports of the client page.
- Hosting rewrites in `firebase.json` for the report paths. The landing page at `/` must keep working.
- The link share from the visit report screen through the OS share sheet, for the production flavor.
- The notice, at the first share, that anyone with the link can open the report.
- A message on the page for a revoked or unknown page ID.

## Out of scope

- A link preview for each report, which needs server rendering.
- View tracking and the confirm button, which belong to M2.
- Link expiry.

## Requirements

- The page works on a phone browser at a 320 pixel width and loads no build step: plain HTML, CSS, and JavaScript.
- The page shows the company name, the client name, the visit date, and each zone's before photo, after photo, and note.
- The footer prints "꼼꼬미로 만든 보고서".
- The page presents no feature of a later milestone as available.
- Do not deploy Hosting. The operator deploys after review.
- Every app string goes in both ARB files, with Korean in polite informal style (해요체).

## Acceptance criteria

- Tests in the app cover the link share, the first-share notice, and the flavors where publishing is unavailable.
- A script or test checks that the page renders a sample report from fixture data without a network.
- `merry run check` passes.
- `merry run coverage` passes at 100 percent.
