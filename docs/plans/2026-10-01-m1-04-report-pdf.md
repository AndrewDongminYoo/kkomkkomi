# M1 brief 4: report PDF and share

Design: `docs/specs/2026-10-01-m1-local-first-design.md`.
Read the design and `CLAUDE.md` before you write code.
This brief depends on briefs 1 to 3, which must be merged first.

## Goal

A worker shares the completion report of a visit as a PDF through the OS share sheet.

## In scope

- `lib/export/`: the report document builder, a deterministic file name, and the A4 PDF renderer.
- Visit report screen: the list of zones that lack a photo, a preview, and the share control.
- A Korean font asset with its license file.
- A share port in `lib/application/` and its `printing` adapter.

## Out of scope

- The web report link, link tracking, and the confirm button.
- The company logo and the monthly bundled PDF, which belong to M2.
- A watermark or a free-tier limit, which belong to M3.

## Requirements

- Add `pdf` and `printing`. Exactly one file under `lib/presentation/` imports `printing`, and a test fails when a second file imports it.
- `lib/export/` imports no Flutter library, and a test fails when it does.
- The report prints the company name, the client name, the visit date, and each zone's before photo, after photo, and note, in zone order.
- A zone with no photo and no note is left out of the report. A zone with only one photo prints an empty slot for the other.
- The footer prints "꼼꼬미로 만든 보고서".
- A missing company name does not block the share: the report screen asks for it and links to the company profile.
- Every user-facing string goes in both ARB files, with Korean in polite informal style (해요체).

## Acceptance criteria

- Tests pin the document structure for a full visit, a visit with missing photos, and a visit with a long note.
- A test renders the PDF and checks that it parses and that its page count is at least one.
- A test pins the file name for a known client and date.
- `merry run check` passes.
- `merry run coverage` passes at 100 percent.
- `CLAUDE.md` describes the `export/` unit and the single `printing` import.
