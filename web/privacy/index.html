이 방침은 꼼꼬미 앱과 웹 보고서 페이지(kkomkkomi.web.app)가 어떤 정보를 어디에 두고, 누구에게 보이며, 언제 지우는지 설명합니다. 앱과 서버 설정의 실제 동작을 기준으로 썼습니다.

1. 휴대폰에 저장하는 정보

앱은 다음 정보를 휴대폰 안의 앱 전용 데이터베이스와 앱 폴더에 저장합니다.

  • 회사 이름
  • 거래처 이름, 구역 이름과 순서
  • 방문 날짜, 구역별 청소 전·후 사진과 메모
  • 게시한 페이지의 ID와 게시 작업의 진행 상태

이 정보는 사용자가 보고서를 링크로 공유하기 전까지 휴대폰 밖으로 보내지 않습니다. 다만 휴대폰의 백업 기능(Android 자동 백업, iCloud 백업)이 켜져 있으면, 휴대폰 운영체제가 이 정보를 사용자 본인의 Google 계정이나 Apple 계정에 백업할 수 있습니다. 운영자는 이 백업을 볼 수 없습니다.

PDF 보고서는 휴대폰에서 만들고, 운영체제의 공유 창으로 사용자가 고른 앱에 보냅니다. 운영자의 서버로는 보내지 않습니다. Android에서는 공유한 PDF 파일이 앱의 임시 폴더에 남고, 앱이 종료되거나 운영체제가 정리할 때 지워집니다.

앱을 삭제하면 휴대폰에 저장한 정보도 함께 지워집니다. 백업에 들어간 사본은 사용자의 계정에 남습니다.

2. 익명 로그인과 사용자 ID

앱은 실행될 때 Firebase Authentication에 익명으로 로그인합니다. 이름, 이메일, 전화번호는 묻지 않습니다. 로그인하면 Firebase가 무작위 사용자 ID를 만들고, 이 ID가 그 휴대폰에서 게시한 페이지의 주인이 됩니다.

Firebase Authentication은 로그인을 처리하면서 IP 주소와 사용자 에이전트(기기와 앱 정보)를 처리하고, 기록한 IP 주소를 몇 주 동안 보관합니다.

이 프로젝트는 익명 계정 자동 정리를 켜 두었습니다. 그래서 익명 계정은 만든 지 30일이 지나면 언제든 삭제될 수 있고, 계정을 계속 쓰고 있어도 마찬가지입니다. 계정이 삭제되면 그 계정으로 게시한 페이지와 보고서는 아무도 수정하거나 닫을 수 없고, 링크는 닫히지 않은 채로 계속 열립니다.

3. 링크로 공유할 때 보내는 정보

방문 보고서 화면에서 "링크로 공유하기"를 누르면, 앱은 그 방문을 Firebase에 올린 뒤 링크를 공유합니다. 거래처마다 고정된 페이지가 하나 있고, 페이지 ID는 128비트 무작위 값입니다. 올리는 정보는 다음과 같습니다.

  • 거래처 페이지: 사용자 ID, 회사 이름(저장한 경우), 거래처 이름, 페이지를 만든 시각, 링크를 닫은 시각(닫은 경우)
  • 방문 보고서: 방문 날짜, 올린 시각, 구역마다 구역 이름, 메모, 청소 전·후 사진의 저장 경로
  • 사진: JPEG 파일. 긴 변 1,600픽셀 이하, 화질 80으로 줄인 사진입니다.

앱은 카메라가 사진 파일에 기록한 정보(촬영 시각, 기기 모델, 그리고 카메라 앱이 기록했다면 촬영 위치)를 지우지 않고 그대로 올립니다. 링크를 가진 사람은 사진 파일을 내려받아 이 정보를 읽을 수 있습니다.

같은 방문을 다시 올리면 보고서를 새 내용으로 바꾸고, 보고서에 더 이상 없는 사진은 서버에서 지웁니다.

4. 볼 수 있는 사람

링크를 가진 사람은 누구나 로그인 없이, 링크가 닫히지 않은 동안 다음을 볼 수 있습니다.

  • 거래처 페이지 문서 전체. 사용자 ID도 여기에 들어 있습니다. 웹 보고서 페이지는 사용자 ID를 화면에 보여 주지 않지만, 링크를 가진 사람은 문서를 직접 읽을 수 있습니다.
  • 그 거래처에 올린 모든 방문 보고서와 사진. 한 방문의 링크만 받은 사람도 같은 거래처의 다른 보고서 목록을 열 수 있습니다.

링크는 추측하기 어렵지만 비밀은 아닙니다. 링크를 전달받은 사람도 열 수 있습니다. 페이지 ID를 모르는 사람은 다른 거래처의 페이지 목록을 볼 수 없습니다.

웹 보고서 페이지와 보고서를 읽는 요청은 Google의 서버로 갑니다. Firebase Hosting은 페이지를 연 사람의 IP 주소를 몇 달 동안 보관합니다. 운영자는 Firebase 프로젝트의 관리자로서 서버에 저장된 정보에 접근할 수 있습니다.

5. 링크 닫기

지금 앱에는 링크를 닫는 기능이 없습니다(예정). 그래서 지금은 한 번 공유한 링크가 계속 열려 있습니다. 링크를 닫거나 정보를 지우려면 운영자에게 요청해야 합니다. [운영자 확인 필요: 닫기·삭제 요청을 처리하는 방법과 기간]

앱의 링크 닫기는 다음과 같이 만들어져 있습니다.

  • 페이지를 닫힌 상태로 표시합니다. 그 뒤로는 누구도 링크로 페이지, 보고서, 사진을 열 수 없습니다.
  • 그 페이지에 앱이 올린 사진을 지웁니다. 지운 사진은 Cloud Storage의 복구 기능 때문에 7일 동안 복구할 수 있는 상태로 남았다가 사라집니다.
  • 거래처 페이지 문서와 보고서 문서는 지우지 않습니다. 보안 규칙이 어떤 문서의 삭제도 허용하지 않기 때문에, 회사 이름, 거래처 이름, 방문 날짜, 구역 이름, 메모, 사용자 ID가 서버에 남습니다. 닫힌 뒤에는 링크로 읽을 수 없고, 운영자만 접근할 수 있습니다.

6. 앱을 삭제하면

앱을 삭제하면 휴대폰에 있던 게시 기록이 지워지고, 익명 계정도 잃을 수 있습니다. 다시 설치한 앱은 이전에 게시한 페이지를 알지 못하고, 새로 만들어진 익명 계정은 이전 계정의 페이지를 수정하거나 닫을 수 없습니다. 그래서 닫지 않은 링크는 계속 열리고, 앱에서는 아무도 그 링크를 닫을 수 없습니다. 익명 계정이 30일 뒤 자동으로 삭제된 경우(2항)도 링크는 같은 상태로 남습니다.

8. 저장 위치, 처리 위탁, 국외 이전

서버 쪽 정보는 Google이 운영하는 Firebase가 처리합니다. Cloud Firestore(페이지와 보고서 문서)와 Cloud Storage(사진)는 서울 리전(asia-northeast3)에 있습니다. Firebase Authentication은 미국의 데이터 센터에서만 운영되므로, 익명 계정 정보는 미국에서 처리됩니다. Firebase Hosting은 Google의 전 세계 인프라에서 운영되므로, 페이지를 연 사람의 IP 주소는 한국 밖에서 처리될 수 있습니다.
